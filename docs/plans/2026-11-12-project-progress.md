# 项目概览：知道卡在哪里，接着做什么

本轮落实[专业团队版 21 天方案](https://github.com/e-dialect/wanyu-proofreader/blob/feat/usability-20261112/docs/plans/2026-11-12-professional-team-21-days.md)中的六环节推进清单。原概览主要依靠条目总数、校对完成数与仲裁数，无法回答来源核验、用途编选和接收反馈是否还有工作。

## 面向使用者的呈现

概览保留全项目条目摘要，增加资料准备、独立校对、仲裁与来源核验、用途编选、交付、接收回执六张卡片。每张卡片提供实际状态、关键数量、处理角色、待处理事项及直接入口。桌面两列、手机单列；需要优先处理的事项放在顶部，其余卡片仍可同时进入。

六张卡片不是单向进度条。团队可以校对已有条目、继续导入新材料，也可以处理历史交付反馈。系统不把这些数量相加成完成率或个人绩效分数。

| 环节 | 从什么记录判断 | 使用者如何继续 |
| --- | --- | --- |
| 资料准备 | 入册条目、导入作业、待确认检查与材料返工 | 查看导入批次或准备材料；历史失败不永久冒充当前阻塞 |
| 独立校对 | 当前轮不同校对者的实际提交与项目所需人数 | 查看待处理条目、安排成员；旧轮提交和仲裁记录不充当独立提交 |
| 仲裁与来源核验 | 当前仲裁、来源核验判据和成员报告的问题 | 打开相应队列；几类数量可能重叠，不合成“剩余条目” |
| 用途编选 | 草稿、当前例外和已有确认记录 | 处理例外、核对当前范围；历史确认不保证现在仍可出包 |
| 交付 | 生成的包及完整交付事件 | 进入交付准备或查看已生成包；生成和下载都不当作接收成功 |
| 接收回执 | 成功回执、实际等待、退回处置、撤回通知 | 定位具体包的事件；退回处置完成不改写为成功接收 |

负责人未分配到具体个人时显示负责角色。状态由业务记录计算，不增加手工勾选“完成”的捷径。统计没有读取到时显示“未更新”，数值保持未知；刷新失败会标明保留的是上次结果，并隐藏旧的优先建议。

## 实现与现有改动的关系

新增只读 `GET /api/fangji/projects/:projectId/workflow`，仅可由当前有管理权限的人读取。复用统一待办的来源核验和交付事件判据，不增加全局项目阶段字段，不修改业务记录、导入、校对、编选或交付权限。

本 PR 基于 #434 的待办分支。#432 的概览方向在这里细化为实际六环节；集成时保留本版概览及 #432 的其他体验改进。材料检查恢复由 #435 实现，本版材料卡仅链接当前分支已有的材料与台账入口，不重复移植导入功能。

## 产品边界与后续验证

概览帮助团队将有出处、可复核的整理成果交接给后续使用者。它不以数量代表语言正确性或文化价值，也不宣称已实现多模态知识生成。

本轮使用隔离服务与合成材料查看实际页面。原方案要求的至少 5 位真人参与、管理员 1 分钟内说清阻塞与处理人，以及真实语言专家和接收方验收仍需另行组织；开发者演练不能代替这些结论。
