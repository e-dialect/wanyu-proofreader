# 工作空间与目录精修验收

本轮以 `83ab4f7` 为基线，精修公共应用壳、工作台、我的任务与项目管理。使用临时后端、虚构账号和 `seed_demo.mjs` 合成材料；截图是 Chromium 真浏览器结果，不是设计稿、真人试用或原生设备验收。

## 对标依据及实际落点

沿用纸色、墨色、朱砂及现有 Reka 封装，借鉴以下官方规范的组织原则，不复制其他产品的品牌外观。

| 官方依据                                                                                  | 本轮实施及可检查标准                                                                                                                                  |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Fluent 2：布局与间距](https://fluent2.microsoft.design/layout)                           | 使用现有 4px 间距刻度表达分组。项目身份、进度、待办和操作各有固定位置；手机摘要为两列，列表操作仍需在 320/390×844 首屏可达。保留 44px 主要触控目标。  |
| [Spectrum：文字系统](https://spectrum.adobe.com/foundations/typography/typography-system) | 标题、正文、元数据通过字号、字重和颜色分工。常规页标题28px、分节/项目标题16.5px，说明13.5px并控制行长，长中文说明使用1.7行高；数字对齐使用等宽数字。  |
| [Fluent 2：动效](https://fluent2.microsoft.design/motion)                                 | 动效只反馈交互：导航/筛选颜色变化，工作台可点击行的箭头轻移2px。沿用120/180/220ms令牌；减少动态效果时取消位移，不为路由、身份变化或请求完成增加等待。 |

## 原有差距与完成内容

- 页眉原先只有重复的页面名。现由既有路由计算“工作空间／校勘工作／项目空间”等上下文，桌面显示层级、手机保留当前页；不读取额外项目列表，也不展示内部项目标识。
- 侧栏主导航原先缺少与平台管理的分组关系。现有明确分区标题、文字与细条双重当前项提示，以及可见的键盘焦点。
- 手机管理统计原先连成多段单位文字。现为具名两列摘要，项目数与材料数分别表达；管理快捷筛选使用轻选中态，突出项目行内的主要行动。
- 任务卡原先把操作名称同时当作状态。现显示真实的进行中、可领取或本人只读状态，项目身份与校对完成比例各有位置；未改变领取、租约或只读逻辑。
- 错误与空结果缺少统一文字层级。`AppStatusPanel` 增加可选标题及紧凑恢复动作布局，保留原角色、插槽和事件；空结果使用标题、原因和恢复入口，不再叠加装饰卡片。

## 浏览器验收

执行：

```bash
NODE_PATH=/private/tmp/wanyu-playwright-runtime/node_modules BROWSER_CHANNEL=msedge \
  python3 backend/tests/run_frontend_quality_browser.py --only workbench components
```

`workbench.cjs` 补充 320px 管理与任务主操作可见、两列摘要、空结果清除恢复及减少动态效果断言。浏览器沿用真实后端，覆盖工作台一击开始/继续、队列 query/hash 恢复、本人只读不写入、项目加入、管理员首页、手机导航、账号替换与编辑器输入可见；公共组件组继续验证菜单/模态焦点、忙碌按钮及 Disclosure 原值/选区。

实际结果：工作台与公共组件浏览器组通过；最终工作台组再次通过，包含侧栏 Tab 焦点、320px 主操作和空结果恢复。`make check`（使用已有 PyYAML 验证环境）及生产构建通过，其中前端单测490/490、31条迁移 up/down/up 均通过。原始断言结果见 [workbench.json](workbench.json)。
