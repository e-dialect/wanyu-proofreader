# 万语校坊产品定位与跨产品边界

> 仓库：`e-dialect/wanyu-proofreader`
>
> 旧产品名：方辑 Fangji
>
> 当前产品名：**万语校坊**
>
> 品牌整合前的旧版源码快照：[fangji-v1.0.0](https://github.com/e-dialect/wanyu-proofreader/releases/tag/fangji-v1.0.0)

## 1. 定位

万语校坊是“乡声万语”体系中面向**方言、地方语言与民族语言资料**的协同校勘平台；“智能协同校勘”是产品方向，不表示当前已经具备成熟的 AI 自动校勘模型。

它解决的不是普通用户随手补充一个词条，而是：

- 成批导入 PDF / CSV 等资料；
- 多人独立校对；
- 可配置校对轮次；
- 差异检测；
- 管理员仲裁；
- 批量导出最终结果；当前导出可按 PDF 页码定位，但不包含逐位校对者尝试与仲裁过程的完整审计记录。字段操作及仲裁来源另有[项目内只读审计与历史字段统计](evidence/issue-185/README.md)，与普通成果文件分开，旧版未记录内容保持未记录。

它有双重但不冲突的身份：

- 对外是可独立部署、独立使用并具有独立商业价值的资料数字化产品；
- 对内是乡声万语 `Candidate → Trusted / Gold` 的专业工作台。

万语校坊项目内的 `approved` 只表示校勘工作流完成，不自动把数据提升为 Trusted 或 Gold。跨产品质量层级仍须经过 [#97](https://github.com/e-dialect/wanyu-proofreader/issues/97) 定义的 provenance、QA、可信/专家决策和版本化流程。

因此它继续保留独立 PocketBase 后端、数据库、认证、权限和专业工作台，不需要为了“品牌统一”强行与乡声集盒合并，也不能降格为乡声集盒的管理后台。

2027 春节阶段使用 **Data First + Product Polish**：用真实莆仙和蒙古语资料验证导入、独立校对、仲裁、导出与志愿者旅程，同时修复产品摩擦，不重写核心架构。执行总控见 [SF-W · 2027 春节万语校坊 Sprint Tracking](https://github.com/e-dialect/wanyu-proofreader/issues/91)。

## 2. 与乡声集盒的分工

### 留在乡声集盒

- 普通用户录音；
- 对本地说法进行轻量确认/反例反馈；
- 高质量成员的一次性补充；
- 与某条 Entry / Recording 紧密绑定、几步即可完成的整理动作；
- 需要最大限度降低用户跳转成本的任务。

### 进入万语校坊

- 一个项目包含大批材料；
- 需要两人及以上独立结果；
- 需要隐藏其他校对者结果以避免相互影响；
- 需要管理员逐字段仲裁；
- 需要进度、租约、批量账号或项目权限；
- 需要批量导出最终校勘成果；如需全过程审计，还应另行导出或保留校对尝试与仲裁记录。

## 3. 登录

- 当前代码保留 `hinghwa` external identity provider，作为历史兼容路径；
- 外部身份按稳定 provider-local subject 映射万语校坊本地用户，不按邮箱或姓名猜测合并；
- 长期方向是以乡声集盒稳定身份作为“乡声万语”主要外部身份入口，但不声称该 SSO 已经实现；
- 万语校坊本地用户、项目角色和独立登录仍保留。

早期不要把两个后端强行合并。身份映射规则必须显式记录，并继续由万语校坊本地权限模型决定项目访问能力。

## 4. 数据交换

近期实行 Review Bundle v0 的人工可控批次交换，而不是实时双向同步。字段契约见 [`plans/2026-09-29-review-bundle-v0.md`](plans/2026-09-29-review-bundle-v0.md)。

下图中 X = 乡声集盒，W = 万语校坊：

```text
X export Review Bundle
→ human check
→ W import
→ independent proofreading
→ arbitration if needed
→ W export Review Result
→ human check
→ X import
```

原则是：**先打通语义，再打通网络。** 春节阶段不建设 realtime API、webhook、message queue、distributed transaction、shared database 或 full OIDC。

每批至少保留：

- source system；
- export batch id；
- schema version；
- source object ids；
- generated-at；
- operator / reviewer；
- checksums（适用时）；
- import result / conflicts。

不允许两端直接读取彼此内部数据库表作为稳定 API。

## 5. 候选任务是否必须进万语校坊？

不必须。

“有高质量管理员/高质量整理成员”并不意味着他的所有动作都要进专业工作台。产品体验优先按**任务复杂度**分流，而不是按**用户身份**分流：

- 轻量、上下文明确、一次完成 → 原地在乡声集盒；
- 成批、需要独立性、仲裁、项目管理 → 万语校坊。

这可以减少两个平台来回跳转，同时保留专业校勘流程的严谨性。


## 6. 初心如何影响产品取舍

乡声万语以地方语言为入口，让与具体地方、人群和生活相连的知识能够被记录、理解和继续使用。万语校坊承担其中的专业整理环节：帮助人们把分散资料变成有出处、能复核、可交接的成果，再进入地方站点、学习工具、文化体验或其他团队的应用。平台的价值也包括让后来者在已有成果上做得更好。

这些方向要体现在日常操作里：

| 设计原则 | 当前与后续功能如何取舍 | 判断是否有用 |
| --- | --- | --- |
| 使用者先获得实际价值 | 校对者能顺手找到原文、输入难字、留住草稿；管理员能接着处理阻塞并找到交付成果 | 使用者能完成自己的工作，少找入口、少重复填写，而非只读到文化使命 |
| 贡献有去处，交接有反馈 | 帮助里说清当前角色与下游使用；报告说明成果范围，回执记录接收方实际结果；后续再研究面向贡献者的去向反馈 | 能回答“我这一步交给谁、对方拿到什么、哪里还需补充”，不把下载当接收 |
| 地方差异值得被保留 | 原文、整理结果、归一建议分层；对分歧保留依据与人工判断，不为了让数据一致而默认改成一种记法 | 可以回到原材料理解不同写法、读法和上下文，未知不会被包装成确定结论 |
| 材料始终带着语境 | 当前保留来源、页码和批次；扩展录音、照片等材料时，再按真实任务增加时间片段、区域、地点或讲述背景 | 切换展示或导出后仍能找回原片段；不强迫每条旧资料补填并不存在的背景 |
| 降低参与门槛，也尊重人的判断 | 简单事情就地完成，复杂批次进入专业工作台；提示解释依据，疑问能交给下一位合适的人 | 新人不必先学完整系统；机器建议不会悄悄变成人的结论 |
| 允许其他团队接着做 | 保持可解释的成果文件与清楚的跨产品边界；用不同语言、文字体系的真实任务修正假设 | 莆仙之外的团队能理解并复用成果，不要求所有内容使用同一种文字或记音方式 |

统计用于帮助团队找到阻塞和继续工作。数量、一致率或速度都不直接代表文化价值、语言正确性或一个人的贡献价值；统一待办不把不同工序的数量加成个人绩效分数。

## 7. 长期方向：从材料片段到有依据的在地知识

“多模态在地文化碎片的知识生成”是长期产品方向。它指向一种可逐步建立的能力：将文字、声音、图像等材料放回具体语境，建立可检查的关联，帮助人理解词语、地名、故事和生活知识。当前平台不承诺已经具备多模态理解、自动知识图谱或可信知识自动生成。

按真实需求逐步推进，不为远期目标提前铺满界面：

1. **现在：让整理与使用衔接。** 优先完成材料导入、原文核验、角色交接、跨项目待办、批次报告和接收回执。现有来源与业务结论应继续清楚可见。
2. **下一步：让片段可定位、可关联。** 在取得代表性材料后，选择一个具体场景，例如“某词条与一段读音、某页图像的对应”。先解决人如何找到、确认和修订对应关系，再决定必要字段和交互；保留未关联、争议和多种解释。
3. **更长期：帮助人生成有依据的知识。** 从已经核定的材料出发，尝试关联解释、学习内容或文化叙事。生成内容标明所依据的片段，允许追问、纠正和撤回；资料事实、参与者解释和机器建议保持可辨。只有实际帮助了使用者，才扩大材料类型和自动化范围。

未来功能进入近期排期前，先说清四件事：谁正在完成什么任务；现在哪里费力；新增能力怎样减少这一步负担；结论如何找回材料依据。长期愿景指导这些选择，不替代当前可用性的打磨。
