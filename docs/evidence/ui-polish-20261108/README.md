# Reka UI 与四个精修样板

基线为 `6fd7e63`。本批完成工作台、项目条目列表、桌面校对和手机尺寸校对；共享字体、控件与动效令牌同步建立。其余旅程的逐页组件迁移不属于本批验收。

## 实现

- Reka UI 固定为2.11.0，Vue peer要求为>=3.4.0，与当前Vue3.5.44匹配；已通过当前Vite生产构建。
- AppButton统一原生按钮；AppSelect/AppDropdown封装Reka的键盘、Portal及焦点行为。空字符串与数值选项保持类型，异步重排保留身份；禁用变化关闭弹层并阻止迟到动作。
- UI、品牌标题、音标/生僻字分别使用字体栈；输入原值、空白和组合符仍由既有内容组件与选择区逻辑承载。
- 工作台单一继续入口、去重项目列表；条目统计收紧，批量/高级筛选默认关闭，普通状态中性呈现。
- 桌面编辑值在前，导入值紧凑对照；textarea根据内容增高，保留176px可滚动上限。手机收起态底部导航与字符入口共用一行，展开后当前输入区仍可见。
- 菜单120ms、托盘180ms轻过渡，支持减少动态效果。没有增加路由、任务或账号切换的延迟卸载。

## 推广与发布边界

以这四个样板为后续页面迁移基准，继续复用公共组件和令牌，按任务大厅、仲裁/核验、管理/交付旅程分批验证。每批保留已有权限、依据、状态与原始字符保护。真实iOS/Android系统键盘、输入法、读屏和3名校对者/2名管理者的真人试用仍需实际设备及参与者完成。

本批不执行生产部署、数据库迁移或数据替换。回滚前端可恢复本批前的`6fd7e63`及匹配锁文件；保留既有后端API与数据。更早的架构改版证据仍在`workbench-experience-20261107/`，不能把本批四样板结果当作全站重新验收。
