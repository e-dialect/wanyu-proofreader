# 统一待办：从跨项目发现问题到继续处理

本轮承接《万语校坊专业团队版：21 天成熟度优化方案》中的统一待处理视图。管理员可从工作台进入一张待办列表，按项目、工序定位当前需要处理的事项，再进入对应的真实业务页面。角色练习和项目内操作衔接见 PR #432，批次报告见 PR #433。

## 使用流程

1. 在工作台打开“统一待办”，查看有管理权限项目中的待处理事项。
2. 根据项目和工序筛选。每行说明项目、事项类型、数量单位、负责角色及下一步，不把不同单位相加成一个含糊的“待办总数”。
3. 点击处理入口，直接进入对应的仲裁范围、来源问题/核验队列、归一复核、编选批次或交付包。
4. 在业务页完成处理，通过顶部“返回统一待办”回到原筛选和页码；重新读取当前业务结果。

## 数量与时间的含义

| 工序 | 数量口径 | 等待时间 | 处理入口 |
| --- | --- | --- | --- |
| 待仲裁 | 当前处于仲裁状态的条目 | 记录中的最近一次差异时间 | 当前待仲裁条目 |
| 来源与成员问题 | 仍需处理的来源问题 | 有确切起点时展示，重新打开但缺少新起点时保留未知 | 来源问题列表 |
| 待核验 | 已有提交、可进入来源核验或仲裁，且按当前来源、依据版本和核验结果仍待处理的条目 | 尚未记录专用开始时间 | 当前待核验队列 |
| 待归一复核 | 当前待复核的归一草稿 | 尚未记录专用开始时间 | 归一复核页 |
| 编选例外 | 可编辑且按当前范围重算仍有待定条目的编选批次 | 尚未记录专用开始时间 | 首个待处理批次的例外页 |
| 待回执 | 当前仍在等待接收结果的交付包 | 交付包生成时间 | 对应交付包详情 |
| 退回待处置 | 尚有未处理退回/冲突或撤回待通知事项的交付包 | 最早未解决事项的登记时间 | 对应交付包的事件与处置 |

同一项目有不同工序时分行呈现；同一条目可以同时需要不同角色工作，不声称这些数量互斥。负责角色依据现有操作权限显示“项目管理员”，没有个人分派记录时不显示虚构负责人。

编选以当前规则和条目状态重算，已确认且不能再修改的批次不列为可处理例外。交付处置以未解决事件为准，已经登记处置的旧冲突不会因历史回执状态仍是冲突而继续出现。下载文件不表示已收到回执。交付详情同步区分待回执、待上游处置、退回已处置与已停用，不让已经退回的包继续显示回执等待时长。

本轮也承接[产品设计原则](https://github.com/e-dialect/wanyu-proofreader/blob/feat/usability-20261112/docs/PRODUCT_POSITIONING.md#6-初心如何影响产品取舍)：让贡献可以顺畅交接，帮助人继续判断，保留材料与处理结果的语境。多模态在地知识生成是长期方向，统一待办只组织现有可处理事项。

## 界面与边界

- 沿用纸色背景、墨色正文、青色主要操作和共享状态组件，按列表呈现事项，手机保留清楚的项目名、数量单位与处理入口。
- 筛选保存在地址中，返回链接限定原项目和工序。切换到无关项目或其他工作时，不继续携带旧待办来源。
- 汇总和分页由后端完成，浏览器不拉取全部条目自行拼数。只返回当前账号有项目管理权限的事项。
- 无记录的时间显示“开始时间未记录”；读取失败显示“未更新”，不显示成没有待办。不同状态不借助颜色单独传达。
- 本轮没有新增自动分派、提醒推送、个人负责人或业务完成按钮。处理仍在对应业务页面进行，并沿用其人工判断与保存流程。
- 来源复核将“可核验或仲裁”与“等待校对”分开；没有首次提交的条目不计为立即可核验，但仍可查看进度、确认空记录或进入项目条目。已处理记录保留在全部范围。
- 拼音归一缺少规则时，已有复核记录、候选和工作区草稿仍可查看。页面在填写前说明由谁准备规则、准备后如何继续；已有对应规则且满足复核条件时，照常人工确认。转换方案是否能用于正式作业由后端实际判据给出，不能使用的方案不提供生成操作。
