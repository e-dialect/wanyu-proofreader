万语校坊：虚构 Review Bundle 全流程练习 v1

这是一份专为软件操作练习生成的合成材料，不是方言语料、真实用户记录、
权利证明或外部验收结果。所有词条和记音均为虚构占位值，无真实身份、账号、
口令、令牌或私人资料。请只在名称含“练习”的独立项目使用，勿混入真实项目。
下载和预检不会自动创建项目、登记来源、授予用途或提交确认。

材料清单
- review-bundle-practice-v1.zip：可直接送入 Review Bundle 预检的完整进入包。
- manifest.json：ReviewBundle/v0 清单与 entries.jsonl 字节数、行数和 SHA-256。
- entries.jsonl：3 条任务，来源编号 practice-001 / practice-002 / practice-003。
- source.pdf：3 页可读虚构原文；每条对应同号 PDF 物理页。
- README.txt：本说明。
ZIP 中的 source.pdf 和 README.txt 不在 manifest.files 内，校验器不会导入它们。
先单独上传 source.pdf；然后上传原始 ZIP，不要把 ZIP 改成 CSV 或改写其内容。

固定来源标识
bundle_id: rb-wanyu-fictional-practice-v1
source_system: wanyu-practice
source_id: fictional-training-only
source_version: practice-v1
rights_ref / 来源逻辑 ID: practice-wanyu-reviewbundle-v1
operator: synthetic-practice-generator（生成工具标签，不是任何人的签名）
requested_fields: page, headword, reading, note
page 只用于 PDF 定位；校对字段为 headword / reading / note，按这个顺序保存。

人员与边界
- 需一名能登记来源及用途的平台注册管理员、一名项目管理员、两名不同账号的
  校对者；同一人可以承担前两种管理职责，但不能用同一账号代替两次独立校对。
- 使用已有、获授权的练习账号；本材料不提供账号，不自动创建成员。
- 来源登记只记录人的判断。PDF 是原文对照材料，不是用途许可或权利证明。
- 复核者、编选确认人和交付核查人必须填写真实操作者的练习署名，不要把
  synthetic-practice-generator 或其他虚构名字当成签字。

1. 创建独立练习项目与上传原文
新建“练习 — Review Bundle v1”，使用默认两人独立校对要求，邀请练习成员。
在资料区上传 source.pdf，等到校验完成，核对总页数为 3，逐页可读。
不要在本练习项目中混入 CSV、其他 Bundle 或其他来源批次。

2. 先预检，确认边界
在“资料导入 → Review Bundle”选择 review-bundle-practice-v1.zip，点击检查。
应看到 ReviewBundle/v0、3 条、上述 bundle_id / rights_ref 和完整来源声明。
核对原文页码 1–3；预检通过只表示格式和清单完整，不代表来源或用途已获批准。
确认框应保持未选中；此时还没有入站作业或条目。

3. 人工登记来源，再决定导入
由平台注册管理员进入“来源登记”，使用准确逻辑 ID practice-wanyu-reviewbundle-v1，
标题填写“虚构练习材料 — Review Bundle v1”，格式填写 jsonl + pdf，范围注明
“软件流程练习，无真实方言或个人资料”。权利主体与证据位置由责任人核实填写，
不要照抄不存在的人或文件。可先保留“待权利确认”，各用途结论仍为“未知”。
如果该逻辑 ID 已存在，先核对它确实对应本版练习材料；不同材料占用时停止，
不要覆盖既有来源，也不要为了通过而关联其他真实材料。
回到资料包面板，再核对声明、项目和 PDF，只有操作者确认后才勾选并导入。
期望入站作业 completed，成功 3、失败 0；记录这个作业编号，后续编选只选它。
找不到 rights_ref 会拒绝导入，不应把来源变成 unknown 来绕过。

4. 建立来源核验约定，独立校对
管理员在项目“来源核验约定”中选择这份已就绪 PDF，核对字段角色；如需记音字段，
将 reading 登记为记音字段并保存当前版本。记音转换不是本练习前提。
两名校对者分别领取、逐字段对照同号 PDF，自己输入并提交；不互相抄写或展示
另一个人的未公开结果。每次的“已对照来源”由实际操作者核对后勾选。
相同结果会完成比较；有差异则进入管理员仲裁，未完成两次提交仍保持待处理。
本包不预填提交结果、来源确认、字段判断、他人提交或已通过状态。

5. 演练差异与来源判断
正常练习允许两人独立得到一致结果。若需专门观察仲裁，另开一轮独立练习项目，
由组织者只向其中一位说明：第二条保留一个明确的练习差异，例如在 note 末尾添加
“ TRAINING DIFFERENCE”；另一位仍按 PDF 独立完成，双方不查看彼此结果。
这是故意制造的软件测试差异，不是对真实校对质量的建议或评价。
管理员只在双方已提交后进入仲裁，对照 PDF 选择最终字段并逐项写明来源判断、
原因和位置，再自行确认；不得仅凭两人一致就冒充来源已核实。
一致完成的条目也可从“来源复核”补录实际来源判断，不确定项保持未核实或待办。
本轮推荐处理完 3 条并保存完整最终行；若仍 withheld、待仲裁或缺少判断，保留阻断。

6. 人工判断用途，观察阻断与解除
先保持来源用途未知，去创建编选预览，确认未知用途不会自动变成允许。
要继续练习，由平台注册管理员依据这份合成材料的范围、所在环境和组织规定，
人工核实来源状态及练习用途；不能判定就停在阻断状态，这也是正确练习结果。
若管理员认定可继续，在来源详情分别记录“内部研究”和“原始材料转交第三方”的
实际结论与依据，来源状态须为“已确认可用”；后者是交付服务的独立闸门，
不能用内部研究许可替代。这里只能针对隔离练习和本地测试接收方作出练习判断，
不代表任何真实资料或外部机构获得授权；不要为了走通流程虚填“允许”。

7. 只编选这一完整入站批次
打开“用途编选”，用途选本次经人工判断的用途，接收方填写“练习本地接收方 — 不外发”。
选择本包完整成功的那个入站作业；采用范围包含已通过的条目。
“要求记音归一已定稿”保持未勾选：这是可选要求，当前样例不依赖任何转换适配器。
核对总数 = 采用 + 排除 + 待处理，三者合计应为 3；数量和理由必须对应实际状态。
处理例外，再由责任人确认编选。来源用途或条目变化后先重新评估、重新确认，
不要沿用旧摘要。未处理条目必须如实保留，不得当作采用正文。

可选的范围处置练习：全部校对完成后，平台管理员可仅对第三条在“条目阻塞结论”
登记 unknown，依据写明“虚构练习：等待补充说明”。编选会保留待处理；经核实可在
该条例外中明确“不进入”，填写练习排除理由与依据，核对从 2 采用 / 0 排除 / 1 待处理
变成 2 / 1 / 0。不要用修改整份来源用途来模拟单条阻断，那会影响同包全部条目。
排除及待处理只声明标识和理由，不作为采用正文交付。

8. 原生交付检查与可选本地出包
从已确认编选批次进入“准备交付”，重新填写本次实际核查人，执行只读预检。
核对接收方、用途、完整批次、3 条范围和采用正文数；包范围不得混入另一个入站批次。
预检失败按实际缺口返回处理；成功也只表示当前服务检查通过，不是外发许可。
只有确实完成核查的人才可勾选确认并生成练习包。下载后保留独立 SHA-256，
检查 manifest 的 result_of.bundle_id 指回 rb-wanyu-fictional-practice-v1，
并检查 delivery.json 的范围、理由、操作者与 human_required 状态。
不把 CSV 导出当作原生交付包；不把下载成功当作消费方导入成功。
如需离线完整性重放，可由工程人员使用仓库 delivery-replay 工具和独立记录的
ZIP SHA-256；它也不替代人工语义检查或消费方验收。
未实际进行外部接收测试时保持“待回执”；不能伪填 success、代签或声称四段真实业务闭环。

重放与清理
同一个项目重复上传同一 bundle_id 会返回原作业，不会重新生成 3 条练习任务。
要从头练习请另建独立练习项目；经核对可复用同一练习来源登记，不改写历史。
已有编选、交付和回执应保留其审计历史，不通过删除记录伪造“重新开始”。
本练习不自动清理草稿、不删除项目、不发外部通知，也不改变真实来源许可。
