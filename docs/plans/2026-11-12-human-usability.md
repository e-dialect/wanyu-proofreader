# 万语校坊：以真实使用体验为主的优化方案

日期：2026-11-12。PR：[#432](https://github.com/e-dialect/wanyu-proofreader/pull/432)。审查基线：`origin/main@36043569fc977e309a74a13c6fe2e578a8c1923d`；本轮实现位于 `feat/usability-20261112`。用户已明确：暂时搁置可靠性等非功能专项，优先操作顺畅和 UI 美观。

## 1. 判断与目标

目前已经具备工作台、项目分区、独立校对、逐字段仲裁、原文对照、专业字符输入、来源核验、用途编选、交付包和回执等基础。主要改善空间在于：把这些能力连成用户容易理解和连续完成的工作，而非继续堆入口。

本方案围绕五个结果：进来知道做什么；填写和查看少往返；下一步随手可达；离开后回来找得到；专业内容看得清、判断有依据。先改善管理员的材料—待办—交付链路，再用真实校对者验证编辑效率。

“国内完全成熟项目”没有统一认证口径。本次选择公开产品文档作为交互参考，不做无依据的成熟度百分比，也不声称已经达到竞品水平。代码与浏览器观察能确认行为，不能替代真人觉得顺畅的证据。

文档解析产品的公开功能不证明其适合本项目的方言、IPA 或蒙古语资料。接入识别之前仍应以实际材料验证人是否少做了整理工作。

## 3. 本轮已经落地

三名 subagent 分别处理材料与帮助、项目推进与待办、编选与交付；主线程集成并进行交叉复核和浏览器检查。实现记录见[验收证据](../evidence/usability-20261112/README.md)。

| 用户遇到的问题 | 本轮改变 | 完成边界 |
| --- | --- | --- |
| 导入预览很长，确认动作容易被挤到后面 | 数量、错误与确认先显示，20 条预览按需展开 | 原始字段、错误提示和人工确认条件保持；不自动导入 |
| 帮助页信息多，难快速找到自己的步骤 | 按项目管理员、校对者、平台管理员组织，格式细节和练习分步展开 | 角色帮助与虚构练习已具备；没有自动安排练习人员 |
| 进入帮助后要重新寻找项目和导入方式 | 帮助入口携带项目及方式，返回原项目的 CSV/PDF/资料包等入口 | 保留导航位置，不声称可恢复浏览器文件选择或未提交文件 |
| 项目概览只有信息，缺少行动顺序 | 紧凑统计、建议下一步、四步推进清单及直接入口 | 推荐依据已有条目统计，不假装知道所有业务环节是否完成 |
| 待办卡片只说明功能，处理优先级不明确 | 任务列表展示四类真实数量，优先打开待处理事项 | 成员按未处理事项计数；未取数明确显示“未读取” |
| 全项目待办数量与点击结果可能不一致 | 全项目仲裁入口清除旧搜索、质量、页码范围及分页条件 | 普通“打开条目”继续保留用户原有筛选 |
| 编选新建成功却出现离开确认 | 成功保存后正常进入详情 | 有未提交改动时仍保留离开确认 |
| 详情刷新或切页后，返回列表位置丢失 | 编选、交付详情携带返回页码 | 已通过状态和路由回归；未承诺所有长列表滚动像素恢复 |
| 重开同一份回执会覆盖正在填写的内容 | 保留草稿并定位登记区；分三组组织字段 | 真实消费方仍需据实登记，不把下载当接收成功 |
| 次要操作和长说明抢占注意力 | 一处突出主动作，更多操作与重发信息折叠；单页回执记录不显示无用分页 | 沿用原有色彩、字号、组件和权限；手机布局已检查 |

发布后追加：已合并 CSV 完成预检中的重复数量与刷新入口，来源、数量、错误和确认集中呈现；过程详情按需展开，正常编码说明保持中性。来源复核与未处理成员问题计数已补齐，仍属于同一前端工作流 PR。

## 5. UI 保持统一且服务于操作

- 保留纸色底、墨色字、朱砂品牌点缀及青色主操作，沿用 `style.css` 的设计令牌。字体、按钮、间距和状态组件继续共用。
- 页面先呈现标题、当前对象、当前状态及下一步。说明放在对应操作附近，低频信息按需展开，阻塞原因不能折叠隐藏。
- 不让每个数字都占一个大卡片；进度用紧凑统计，连续事项用列表，真正需要决定的步骤才突出。
- 每个操作区域突出一个主要动作，其余用次级按钮或文字入口。确认文案说清结果，不用“确定”掩盖生成、提交或改动的区别。
- 移动端先保证主要动作和字段可操作，主要触控目标至少 44px；长内容可换行，原文与表格在局部处理滚动，避免整页横向溢出。
- 保留键盘焦点、可访问名称与文字状态。采用建议、展开预览、查看原文都不能偷偷提交或改变核对结论。
- 视觉验收覆盖桌面 1440px、手机 390px 和窄屏 320px；浏览器模拟与真实设备验收分开记录。

## 6. 三个阶段的推进安排

按约三周工作窗口组织，前端/产品可并行，语言专家和试用者的排期是关键依赖。复杂识别、多批次、自动回传仅做验证和设计，不承诺三周全部上线。

| 阶段 | 工作 | 阶段交付 | 放行条件 |
| --- | --- | --- | --- |
| 第 1 周：让现有流程连贯 | 合入本轮交互改进；安排 5 人首次试用；补完整待办和易发现的导航断点 | 本轮代码与截图、问题清单、任务完成基线 | 明确每个失败步骤和责任人，修复后能够继续原工作 |
| 第 2 周：减少高频操作负担 | 根据观察优化原文定位、字段切换和材料预览；补专业字符项目示例、练习清单 | 两条主要用户路径、材料准备原型、经核定的说明 | 同任务复测，求助与错误往返减少；专业字符保持原值 |
| 第 3 周：交接与复测 | 做批次就绪清单原型；让接收方走一次真实流程；复测手机和桌面 | 修订后的流程、真人验收记录、剩余问题排期 | 至少 4/5 人独立完成相应任务；无法继续、丢失输入、误解完成状态的问题全部整改并复测 |

建议单项改动控制在约 0.5—3 个开发工作日可评审的范围，材料区域/列映射等较大项先交互原型后拆分。未取得试用排期时继续完成代码及可检查演示，真人结论保持待验。

## 7. 用真人任务衡量是否更好用

沿用[既有真人验收表](../evidence/workbench-experience-20261107/human-acceptance.md)，先招募 3 名校对者和 2 名管理员，莆仙为主试点，蒙古语补充。使用授权或虚构材料，不把真实内容、身份和口令写入仓库。小样本用于发现问题，不做总体人群的统计承诺。

| 任务 | 测量方法 | 建议验收目标（不是当前实测值） |
| --- | --- | --- |
| 找到并继续工作 | 记录首次进入到打开当前任务的耗时、错误入口和求助 | 至少 4/5 人独立找到对应工作；阻断问题清零 |
| 准备并导入材料 | 从选文件到预检确认，记录对数量、页码、跳过原因的理解 | 使用者能解释导入范围，并自行定位一处预设格式问题 |
| 完成一条校对 | 记录切原文次数、找字符耗时、误提交和处理时间 | 在准确性不下降前提下改善相对基线；目标可先定中位耗时减少 20%，待测后调整 |
| 处理仲裁 | 从待办数量进入一条分歧并提交结论 | 列表范围一致，能够判断未决字段并完成处理 |
| 编选和交付 | 从已完成任务找到可交付范围、下载，再登记实际回执 | 能区分校对完成、用途可用、生成包和接收成功 |
| 中途离开再回来 | 进入详情、刷新、返回列表、重开同一回执 | 返回正确工作位置；未提交输入不被同页重复入口覆盖 |

每次记录：任务版本、设备、是否首次使用、完成/未完成、耗时、提示次数、误操作、原话及问题复测。完成后的单题易用度可用 1—7 分，建议中位数至少 5；它仅作补充，不能抵消任务失败。对耗时采用同难度且顺序平衡的两组材料，避免把第二次熟悉任务当作产品提效。

可靠性、压测、灾备、监控和架构扩展本阶段不单列工作包。已有数据与独立判断约束继续保持；只修复本轮改动直接引入的操作回归。本轮自动检查及合成数据验收已完成，真实试用、真机/读屏和真实接收方验收仍待执行。
