# 材料准备续接：操作记录

本轮由 AI 在隔离服务与真实 Chromium 浏览器中操作，使用仓库虚构练习资料的副本、合成来源和合成账号，没有使用生产资料。这是功能与界面证据，尚未开展真实管理员的独立使用验收。

## 已走通的使用路径

**找回原文、预览与继续处理。** 项目预先已有 3 页主 PDF，重新进入来源 PDF 页面显示文件名、物理页数与校验时间，不要求再次上传。点击预览后实际显示原文，连续到第 3 页，末页“下一页”禁用；关闭预览后焦点回到入口。点击“继续导入 CSV”和“去 PDF 文字提取”均进入同一项目的相应页面。本轮核对入口与现有功能说明，没有执行一次新的文字提取作业。

**更换失败仍能继续。** 实际上传一份故意损坏的合成 PDF，后台校验失败；页面解释当前主 PDF 仍可使用。刷新后仍能看见失败提示和原 3 页主文件。随后实际上传有效的 4 页替换文件，校验成功后显示新主文件；再次刷新仍显示新文件，旧失败提示不再出现。未完成分片和处理中记录的恢复逻辑沿用已有服务并经代码复核，本轮未制造长时间处理任务来单独验证该过程。

**旧文件缺少页数记录。** 在隔离数据库暂时清空上述合成文件的页数和校验时间，模拟旧记录。主卡明确显示页数未记录；打开预览后读到实际 4 页，能够翻到第 2 页。此过程不回写页数，走查后已恢复合成记录原有元数据。

**来源缺项到继续导入。** 选择包含 3 条虚构条目的 ZIP，格式检查通过后读取来源登记，未登记时禁用确认。由合成平台管理员新窗口打开来源登记，登记标识准确预填，标题和用途结论没有自动填入。填写合成来源标题并登记，切回原页后 ZIP 仍在；重新检查来源、确认导入，结果为成功 3 条、失败 0 条。

**导入后查看本批。** 再次提交同包返回已有作业，点击“查看本批条目”进入带 `importJob` 的项目条目页，显示“仅查看本批次”和当前条件 3 条，没有弹出未完成资料包的离开提醒。

**项目管理员的实际界面。** 另用合成项目管理员账号选择另一份声明来源缺失的 ZIP，界面明确提示联系平台管理员。新窗口显示所需登记标识，未显示“登记来源”按钮；原页继续保留 ZIP。来源是否存在和用途是否获准分别描述。

## 必要检查与边界

前端 lint、构建和 13 项相关既有检查通过，后续新增结果入口的 Bundle 既有 7 项检查通过；Go `reviewbundle` 包检查通过。检查过程仍以真实界面操作为主，没有新增测试套件或开展可靠性专项。

已尝试 `make check`，本机缺少 PyYAML，停在 `verify-static` 入口，不能视为完整门禁通过。预检仍不写入数据；新增 `rights_ref` 仅返回资料包中已有声明，不读取来源数据库。原文预览仍使用管理员原有文件权限，来源登记仍只有平台管理员可写，无 schema 或环境变量变更。

本切片基于 PR #435 的 `10222bb`。长期多模态文化知识生成、真实资料权利确认和真人体验验收均不由这些合成结果代替。
