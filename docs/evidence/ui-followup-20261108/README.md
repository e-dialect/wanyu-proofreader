## UI 下一轮建议

在本机实际运行的合并版本检查了工作台、我的任务、我的项目及桌面/390×844校对，使用既有虚构项目、13条材料和测试PDF。当前四样板清楚，但任务与项目页仍保留较重的统计卡片、左侧色边及不同的按钮样式；页标题、最大内容宽度和信息密度也未统一。这是下一轮精修最直接的落点。

1. **先统一高频外围页。** 从“我的任务、我的项目、仲裁/来源复核入口”开始，复用现有AppButton/AppSelect/AppDropdown与统一页宽、标题、行高、边框和主操作色；统计收为摘要，每处突出一个主要动作。保持项目级权限与原URL语义。
2. **增强手机提交路径的可发现性。** 当前逐字段→整条总览→检查并提交的行为可用，但首个字段只见方向图标。应让当前步骤和终点可见，提供清楚的总览入口，保持输入与字符托盘位置，不让提示占据编辑主体。
3. **统一保存与恢复反馈。** 草稿保存、提交、离线、租约失效使用稳定位置及具体恢复动作；操作错误贴近表单，成功反馈不挡正文。来源未配置、待核验、结果一致和质量通过分别表意。
4. **让动效帮助定位。** 沿用120/180/220ms与减少动态效果设置，只给菜单、展开和真实状态变化轻反馈；不添加任务/账号/权限切换延迟卸载。现有Reka已承担焦点、键盘与弹层原语，下一轮重点在仓内视觉与业务编排，不增加另一套组件库。

Reka的可及性职责见[官方说明](https://reka-ui.com/docs/overview/accessibility)；Vue已有[进入/离开过渡](https://vuejs.org/guide/built-ins/transition.html)能力。它们不代替本产品的可访问名称、业务状态和原生设备验收。
