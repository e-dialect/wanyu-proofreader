# 问题与草稿：看清反馈，继续原来的工作

本轮承接[真实使用体验方案](2026-11-12-human-usability.md)中的疑点反馈、未完成工作与导航衔接。原列表只显示条目号，跨项目同号难以区分；所有记录都提供恢复按钮，已经提交或不能恢复时，用户要先点一次才知道原因。

## 使用过程

1. 从“我的任务”进入“问题与草稿”，保留原来的搜索、项目、页码与视图。
2. 每条记录显示项目名、条目号、问题内容和管理员反馈；可按项目以及草稿／问题反馈切换。两类记录分别计数，不相加为任务总量。
3. 能恢复的条目提供恢复操作，成功后才进入编辑器；已提交的条目直接只读回看本人版本。被排除、退回资料准备或暂由他人持有时，直接说明当前情况。
4. 同项目还有在手任务时，先进入该任务。本人已经持有本条时，使用“继续当前在手条目”，避免重复恢复让原编辑页无法提交。新标签缺少当前领取信息时，先说明回原页继续或主动重新领取的影响。
5. 恢复失败在对应行显示，保留反馈与筛选。编辑、释放或回看结束后返回原问题列表，再回到原任务大厅条件。

## 与产品方向的关系

报告问题也是有价值的贡献。校对者应能找到自己提出的问题、知道团队如何回应，并带着上下文继续工作。管理员反馈不等于资料已经校对正确，草稿也不计作正式提交；界面应帮助人完成判断，而不是用一个“已处理”标记掩盖后续工作。

## 范围与衔接

本轮在任务项目搜索与本人提交记录之后实现，采用线性依赖 PR。复用现有报告、草稿、领取和只读回看接口；问题列表增加项目名称和可用动作，恢复资格与列表共用判断。没有新迁移，没有新增替他人恢复或查看他人答案的权限。

界面继续使用现有纸色、青色与共享组件。真实操作与手机截图见[操作记录](../evidence/problem-followup-20261112/README.md)。真人试用与授权方言材料的反馈仍需另行组织。

## 后续已发现的问题

- **材料补录优先继续处理**：CSV 部分成功后仍可能提示修改整份文件重传；新批次会追加成功行。应区分预检修正与失败行补录，并让资料负责人容易拿到中文错误清单。证据位于材料续接分支的 `ProjectCsvImport.vue` 与 `import_service.go`，本 PR 不改变导入行为。
- **台账错误定位**：长批次列表点击“查看错误”后，错误面板在整表后方；应直接定位并提供回到所选批次的入口。
- **重新领取原条**：既有编辑器的主动重新领取仍请求项目领取接口，原条不可用时可能返回其他条目。本轮只阻止问题列表重复恢复有效在手任务；精确重新领取原条需要独立完善。
