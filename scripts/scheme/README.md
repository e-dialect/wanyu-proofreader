# 声调记法转换（tone notation codec）

把记音列里的**数字声调**与印出样式所需的**上标声调**互相转换。这是 #114/#189「拼音方案归一化转换」的**离线一侧**：读真实语料、量出歧义面、产出可审阅的规则文件。

**它不是产品代码**：不参与导入、校对、仲裁，不写库，也不改任何原始值。#189 把平台引擎定在 Go（`backend/scheme/`），本包是喂给它的前置证据与规则草案，两边各自加载同一份规则文件。

只用 Python 标准库，未新增任何依赖。

## 为什么需要它

《莆仙方言大词典》凡例三.1：**「声调采用调值标注法，标在拼音或国际音标的右上角（上标）」**。而 CSV 导出把上标全部降级成了普通数字——实测三列中**已含上标数字的单元格为 0**，即整份导出 100% 处于压平态。要还原成书上的样子，需要一次覆盖约 9.15 万个调值的批量转换，且必须可复核。

```
# 下面用的是 fixtures/mini_tones.csv 的合成值，不是词典正文
书上的样子   qa⁵³³      ← 调值排在右上角，是上标小数字
CSV 里的样子 qa533      ← 导出把上标降级成了普通数字
```

## 一条硬规矩：不猜

`4213` 这一串数字，在莆田调值集合里既能读成 `42+13` 也能读成 `4+2+13`。区别在于中间那个音节的**字母丢了**——那是损坏，不是一道该由程序解的题。所以：

| 情况 | 判定 | 单元格 |
| --- | --- | --- |
| 数字串本身就是该列的一个合法调值 | `EXACT` | 转换 |
| 数字串只能读成 ≥2 个调值挤在一格 | `AMBIGUOUS` | **一字不动** |
| 数字串读不成任何合法调值 | `UNSUPPORTED` | **一字不动** |
| 没有数字串（含已是上标、只有占位符） | `NO_TONE` | 一字不动 |

状态沿用 #114 §5 的枚举，不另造一套。**一个单元格里只要有一格判坏，整格就不转**——半转换的单元格比不转换更糟，因为它看起来像已经处理过了。

`@NNNN` 缺字登记号的数字**永不参与转换**（凡例：它是源库登记序号，不是 Unicode 码点）。占位符正则的下界刻意取 2：仓库内 `corpus_probe/detectors.py` 用 `@[\da-fA-F]{3,6}`，未入仓的 `w2_parser.py` 用 `@(\d{2,6})`，两者在这份语料上实测等价但定义不一致，转换器多保护几个字符零成本、少保护一个就会把登记号印成上标。

**上界不设限，而是超过 6 位就整格拒绝**（`UNSUPPORTED / placeholder_out_of_spec_length`）。因为 `5`、`3` 本身也是十六进制字符，`@ABCDEF533` 到底是「9 位登记号」还是「6 位登记号 + 声调 533」从字符串上无法判定；而 `533` 恰好是合法调值，按 `{2,6}` 截断匹配会**静默**产出 `@ABCDEF⁵³³` 且状态 `EXACT`——更糟的是 `flatten()` 两个方向都能回到原值，`verify()` 也看不见它。这条是 #249 评审提出并在合并后补上的。

## 规则文件与它的出处

`data/tone_notation.json` 是唯一规则来源，代码里没有硬编码的调值表。

- **每列一套合法调值**，不是一套全局：`拼音`/`莆田IPA` 用莆田集，`仙游IPA` 用仙游集。依据是凡例三.1「**拼音中的声调统一采用莆田话的调值**」，以及仙游有 23/2 两个莆田没有的调值、莆田有 4/1 两个仙游没有的。
- **`puxian-wendu`（《文读字汇》）被显式拒绝**。那套用 1–7 标**调类**（阴平…阳入），大词典用数字标**调值**：同一个 `qa²`，在前者是阳平，在后者是阳入调值。**同形不同义，看字符串无法区分**，所以方案必须由人声明。#189 非目标「不自动判断某书用什么方案」在这里是可执行的，不是客套。
- **上标字符集从键盘定义读**，不写死：`load_superscript_map()` 从 `backend/keyboards/hinghwa-dialect.json` 的 `superscript-digits` 段取可用字符，按 Unicode 名称（`SUPERSCRIPT ZERO`…）识别。莆仙键盘当前有 `⁰–⁸`、**没有 `⁹`**，所以真需要 ⁹ 时结果是 `UNSUPPORTED / superscript_untypeable:9`，而不是偷偷产出一个校对员敲不出来的字符。
- `long_tones` 与 `detectors.LEGAL_LONG_TONES` 的一致性由 `test_long_tones_agree_with_the_shared_detector_constant` 钉住。#189 提醒过"一套定义两处使用"会漂成两份实现，这根桩就是防它漂的。

## 用法

```bash
python3 scripts/scheme/convert_tones.py --csv /path/to/正本.csv            # 只出统计，不写文件
python3 scripts/scheme/convert_tones.py --csv ... --direction flatten      # 上标 → 数字（比较键）
python3 scripts/scheme/convert_tones.py --csv ... --out /tmp/正本.上标.csv  # 写新文件
python3 scripts/scheme/convert_tones.py --csv ... --json
```

输入优先级 `--csv PATH` > `$WANYU_CORPUS_CSV` > 报错，**没有默认值**（沿用 `corpus_probe/input_source.py`，默认值曾把作者本机的用户名和会话 ID 写死进代码）。规则文件 `--rules`、键盘 `--keyboard`、方案 `--scheme` 同理可覆盖。

写文件有三道闸：

1. `--out` 落在仓库内 → 拒绝（`CONTRIBUTING.md:139`「不提交真实语料」、`ASSET_BOUNDARIES.md:28` 的资产边界、#92 权利矩阵）；
2. `--out` 等于输入本身 → 拒绝；
3. 落笔前跑 `verify()`：行数不变、每个非目标列逐格不变、每个目标列 `flatten(前) == flatten(后)`。任何一条不过就**不写**并退出 2。

第 3 条那个不变式值得单独说：升调只能改变一个数字**怎么写**，不能改变**有哪些数字、什么顺序**。这比"看起来差不多"强，且能抓住丢位。

## 输出纪律

与 `corpus_probe` 一致：两种模式都只含**文件名（非路径）**、计数、调值直方图与码位，**不含单元格原文**。sha256 的口径也照 `corpus_probe` 走，不在两个包之间各说一套：人读输出打**前缀 16 位**，`--json` 打**完整 digest**（`probe_corpus.py:100` 同此）。只有 `--show-samples N` 才打印原文，并在 stderr 警告勿粘贴。理由一样：这类诊断会被粘进 issue，而语料的权利状态未定（#92）。

## 在正本上的实测（15,022 条逻辑记录）

| 列 | 非空 | `EXACT` | `AMBIGUOUS` | `UNSUPPORTED` | 空 |
| --- | --- | --- | --- | --- | --- |
| `拼音` | 15,022 | 15,019 (99.98%) | 1 | 2 | 0 |
| `莆田IPA` | 12,630 | 12,628 | 0 | 2 | 2,392 (15.9%) |
| `仙游IPA` | 12,795 | 12,778 | 0 | 17 | 2,227 (14.8%) |

合计 **40,447 个非空记音单元格，22 格拒绝（0.05%），约 91,508 个调值升为上标**。

两处独立实现对齐过，所以这些数字可用：本表 `莆田IPA`/`仙游IPA` 的非空数（12,630 / 12,795）与另一套独立探针逐列统计完全一致；`15,022` 条逻辑记录与 `10_真实语料实测结果_S2.md`（仓库外）一致。

**本文件有意不写正本的文件名与 sha256**：文件指纹能唯一标识一份权利状态未定的资料（#92），且 `10_…` 报告在公开 issue 里也按同一口径省略了它。要复算这些数字，跑一次 CLI，首行就会打出 sha256 前缀。

22 个拒绝格几乎全是**跨方案调值越界**：`仙游IPA` 里出现 14 次莆田独有的入声调值 `4`、1 次 `1`、1 次 `24`；`拼音`/`莆田IPA` 里出现只属于仙游的 `23`。这与 R6 `detect_illegal_tone_runs` 报的 12 条 `reading_format_invalid` **不是同一批**——R6 只看「≥3 位且不是 533/453」，看不见 1–2 位调值串了方言。是否值得为它单立一个 kind，交 #176 判。

## 本包没做、但已经定位的事

按"能不能从凡例直接读出来"排序：

1. **拼音方案 ↔ IPA 的对应表**：凡例三.1 明写「莆仙方言拼音方案与国际音标的对应关系等，**请参见附录**」。那张表在扫描版正文的附录里，本包没碰。语料本身也给了平行样本：`拼音` 与 `莆田IPA` 音节数一致率 **99.94%**（12,622/12,630），可直接抽成约 2.85 万对音节级对齐语料。
2. **例句分隔符三方不一致**：凡例四.5 规定用 `丨`(U+4E28)，正本实测 `丨` 仅 **2** 处、`∣`(U+2223) **29** 处、ASCII `|` **740** 处、全角 `｜` **0** 处；而键盘 hint 专门区分 `∣` 与 `|`。到底认哪个为准是**裁定项**，不是转换器能定的（R-SYMBOL 的同类问题）。
3. **凡例符号表的还原**：六、符号给出 `【】`外括号、`（）`两种用途（表地域 / 解释例词）、`‖`补充说明、`▲`也念、`◆`也说、`■`〔莆〕说〔仙〕说、`●`另见。正本实测 `‖`3,454 格、`◆`760、`●`523、`■`420、`▲`222。另有 **37 格标记与它该带的动词不成对**：有`▲`却无「也念」13 格、有「也念」却无`▲`3 格、有`◆`却无「也说」6 格、有「也说」却无`◆`15 格（`●`/「另见」523 格完全成对）。像是导出丢符号，但"标记后接别的动词"也解释得通，得人工看一眼才能定性。
4. **凡例二.2 的合音词靠加下划线标记，CSV 导出丢掉了下划线，因此不可还原**。同类不可还原的还有：词头的借音字/借用字/训读字/方言俗字类别只有一部分在 `‖` 后标了。凡例同时警告「对词头的理解，不可望文生义，还是应该以标音和释义为准」。
5. **繁简归一会撞 R-DEDUP**：凡例二.2 明列 面/麵、呆/獃、只/隻 在本词典里是**不同词头**。任何"顺手做个繁简转换"的想法都会把它们并错。
6. **凡例五.2 的排序规则未验证成功**：它说按拉丁字母序、同音节再按声调、音变新调值 55 在阴阳上去入之后、轻声在 55 之后。我用码位序比较（含去声调的字母键）得到 4,354 处逆序相邻对——**这说明我的比较法不成立**（词典的字母序不是码位序，`ɑ` 与 `a` 的先后要看书后的音系说明），不能据此说语料违反凡例。定 collation 需要附录。
7. **记音列被 `…`(U+2026) 截断**：`拼音` 11 格、`莆田IPA` 10 格、`仙游IPA` 11 格，且绝大多数在末尾，像是导出截断。现有 R1/R6 都看不见它。
8. **8 行的 `莆田IPA` 里内嵌 `]〔仙〕｛…` 异读**（把仙游读法塞进了莆田列），也正是音节对齐唯一失败的 8 行。`detect_column_collapse` 的 `unbalanced_bracket` 能碰到它们，但语义（一个单元格两个地域）没有 kind 承载。
