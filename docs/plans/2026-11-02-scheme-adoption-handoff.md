## C 接口准备（#364 → #365 → D）

复用 [运行面](../../backend/scheme_conversion.go)、[转换结果](../../backend/scheme/convert.go)
和 [v2 来源规则](../../backend/scheme/adapter_v2.go)。下表区分现有数据与待确认的交接约束。

| 项目 | 现有依据 / 待确认要求 |
| --- | --- |
| 规则与门禁 | 对齐 `source_scheme_id`、schema/rule version、`rule_status` / `rule_status_basis`、provenance/basis、目标 inventory。已有 `jobAdapter` 检查 production 声明与真实作业 schema；不能把 synthetic/v1 改标签当真实规则。正式规则可用性和处理许可仍须核实。 |
| 结果定位 | 运行面已有条目 ID、原值快照、源字段、源/目标方案、归一值、`normalization_status`、规则版本、trace、候选及人工依据/复核人/时间。`normalizationView` 未返回源字段与作业引用等所有定位信息；异常清单的字段/批次定位须补充约定。 |
| 四态 | 保留 EXACT / REVIEWED / AMBIGUOUS / UNSUPPORTED。后两类不能带猜测的确定归一值；前两类也不自动表示本批可采用或可发布。 |
| 分段失败 | 保留 `source_to_ipa:*` 与 `ipa_to_target:*` 的原始 trace/decline，分别说明源侧依据不足和目标侧无法表达；不合并成一个泛化失败。 |
| C→D 理由 | 当前 D 的 `requirePinyin` 只看是否为 EXACT/REVIEWED，其余归入 `pinyin_pending`，尚未直接引用 C 的细分异常。双方需交付“状态＋原始原因 → 同源 D 理由/引用”的对照及无法映射项，不改写 B 的 `blocked_reason`，新增理由沿 D3.3 讨论。 |
| 计数与重跑 | 完成作业的 `total = exact + reviewed + ambiguous + unsupported + skipped + failed`。人工已复核的条目重跑归 skipped，不再次计 reviewed。另说明候选总量、取消/恢复/部分失败的实际覆盖范围；作业计数与当前条目四态库存不能混作同一分母。 |

## D→E 待确认差异

复用 [D 编选](../../backend/adoption.go)、[E 服务](../../backend/delivery_service.go)
和 [现有交付说明](../release-delivery.md)。下表为对齐清单，不在此新增请求字段、接口或理由枚举。

| 差异 | 当前行为 | 核对后需要形成的交接结论 |
| --- | --- | --- |
| 范围 / 分母 | D 对项目计算，`importJobs` 外成员也归排除；E 首版只接一个完整成功的 ReviewBundle 导入批次 | 明确同一批的成员集合及分母，再核对 `total = selected + excluded + pending`；不把项目总数直接当 E 单批总数。多批/CSV 等不支持情况显式保留缺口。 |
| 成果条件 | D 默认规则含 proofread/approved；E 采用正文要求 approved、非 withheld，并满足现有业务完成门槛 | 约定不能交付时的拒绝/回流及重新确认方式；不为出包修改 B，也不由 E 擅自重判 D。 |
| 分类 / 理由 | D 使用 selected/excluded/pending；E 使用 adopted/excluded/pending。D 理由还含结构与用途码，E 当前仅接受阻塞词表 | 明确 selected→adopted 的字段转换、pending 优先识别及原因无损引用。不能把不认识的原因统一压成 unknown，也不能另造平行词表。 |
| 完整声明 / 权限 | D 默认 manifest 只含 selected，范围外仅有 omitted；`include=all` 仅平台管理员可用。E 要逐项核对整批 | 约定鉴权的完整分类投影及条目标识，不以提升所有 manager 权限解决接口缺口；范围外/待处理默认只声明标识和理由，不携带正文。 |
| 权威 / 确认 | E 现有 `confirmed_by` 是人工交接署名；D 有批次确认记录、计数及 `scope_digest` | 明确可验证的批次引用、用途/接收方、规则、确认人/时间及成员凭据。E 从 D 服务端复核，不能把人工字符串当权威；未确认、漂移或旧空指纹的处理须明示。 |
| 权利 / 历史 | D 有 `rights_changed` / `reevaluated`；E 已有权利复核、包停用、通知凭据、重发及回执 | D 给出影响批次，E 对应到已交付包并追加处置。许可 unknown/deny 不放行；不得改写历史或把“待通知”记作已通知。 |

现有默认 manifest **不能直接替换** E 的整批人工交接清单：它既不含完整分类，也没有消除分母、理由、确认与权限差异。
接口确认及实现完成前，保留人工交接的明确标识，不宣称 D/E 权威对账完成。

## 联调验收准备

以下均为**后续待执行**用例，本次文档没有生成业务产物或宣称通过。

| 场景 | 必须保留的证据 |
| --- | --- |
| 同输入、同规则重复运行；已有人工复核重跑；取消/恢复/部分失败 | 四态、skipped/failed、候选与已处理分母，不重复计数；规则版本及原值一致性 |
| 歧义、不支持及两段分别失败 | 无猜测的确定值；原原因、trace、条目与字段可定位，C→D 对照不丢原因 |
| 同一批含采用/排除/待处理 | 两侧同批成员及三类数量一致；部分范围和 omitted 明示，不冒充全量 |
| 未确认、等数量换成员、旧空指纹、预检后发生变化 | E 不沿用失效的人工确认/预检；拒绝或回流后有明确的新确认凭据 |
| 权利 unknown/deny、例外选入后撤权、影响已交付包 | 不经例外放行；D 影响批次与 E 包可追溯，历史保留、处置追加 |
| 五种身份、范围外声明、B 成果不变 | 平台管理员、无 manager 成员行的 owner、manager、校对员、非成员各测；不泄露正文或盲校线索，B 原值/校对行/提交记录不变 |

先用明确标为测试的合成数据联调，再使用已获准的真实批次；合成结果不替代真实资料、真人、X 侧 dry-run 或签字验收。
后续 PR 记录具体执行的命令、结果、产物和遗留项；不以历史全绿代替本次实测。
