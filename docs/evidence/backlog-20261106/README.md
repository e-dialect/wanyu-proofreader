## 可复现执行

`backend/tests/backlog_browser.cjs` 接在原质量状态集成之后，先做选择/范围/搜索/保留旧值重试/服务端导出/布局检查，再执行原 `quality_state_browser.cjs` 六个状态用例。所有账号、项目和 CSV 都由一次性 harness 生成；图片不含真实账号或语料。

OCR 浏览器链使用 `python3 backend/tests/run_ocr_browser.py`，需构建好的 SPA、Playwright 和 Docker；可用 `OCR_BROWSER_IMAGE` 指定刚从本 checkout 构建的镜像。worker 端口只映射临时 loopback，非生产 Compose；结束自动删除容器与数据库。见 [OCR UI 记录](../ocr-runtime-ui/README.md)。

## 收口时发现并修复的实际边界

- 质量状态与导入值修正：提交期间禁止 Esc/backdrop 关闭或换目标；捕获原目标/版本/载荷，卸载后的迟到响应不改写新目标。真实生产处理函数有延迟响应与失败重试测试。
- 列表翻页：已显示页/offset 与请求目标分开；目标页失败仍显示最后成功页，重试针对失败目标，不把第1页数据标成第2页。
- OCR 发起：每次明确发起有 requestId；服务端按项目/操作者/请求ID幂等，成功、处理中和失败终态都返回原作业。浏览器在POST前保存本次请求，响应未知时先确认同一次请求；刷新也恢复同一意图，不新建重复批次。
- 安全补丁：可达 Go 漏洞通过 Go1.27.3 与 x/net0.62.0 修复；govulncheck最终可达与imported-package漏洞为0。开发工具 minimatch 的兼容修复状态见质量记录，不把不可达/开发依赖与产品运行时混为一谈。
