## 下一轮 UI 的三个优先项

1. **把已定好的公共控件用于高频管理表单/菜单，减少原生控件与新控件混排。** 先做当前真实易出错的导入错误/重试、仲裁与交付入口，逐页保留数据/权限/状态保护；不一口气全站机械替换，也不改 textarea 输入底座。
2. **统一内容密度和响应式动作位置。** 当前 AdoptionView 1144 行、ProjectSettingsView 1161 行、DeliveriesView 806 行等仍承载大量表单/解释，视觉上最容易延续“碎”。先明确每视图当前步骤和一个主动作，次级说明/配置按需展开，并把状态与操作失败反馈贴近相关内容；拆组件以具体旅程为边界。
3. **完成低干扰的反馈与连续操作。** 动效沿现120/180/220ms规则，优先菜单、展开/折叠与实际保存结果，保证当前字段可见、队列返回上下文和焦点稳定；先核销“无效提示”“整页横滚”“失败不知如何继续”等真实摩擦。新动效不能给任务/账号权限失效增加延迟卸载，原生手机键盘与真人试用仍单列。
