# 批次报告：看清进度并继续处理

这项工作承接[专业团队版21天方案](https://github.com/e-dialect/wanyu-proofreader/blob/feat/usability-20261112/docs/plans/2026-11-12-professional-team-21-days.md)的第三项产品改进。当前按用户后续要求，优先解决实际操作问题。报告、导出和继续处理放在一个独立 PR；角色练习等前端流程整理在 [#432](https://github.com/e-dialect/wanyu-proofreader/pull/432)。

## 用户怎么用

1. 在项目的「材料 → 导入批次」中，直接从首列打开「质量与交付报告」。台账状态用中文显示，窄屏也能找到报告入口。
2. 首屏看当前批次是否仍待确认、校对是否完成、有没有待仲裁或待回执。根据提示继续处理；进入条目和连续仲裁时保留本批范围。
3. 按需查看导入对账、独立提交覆盖、来源判断、编选和交付记录。总量用数量呈现，覆盖量显示分母；无待办显示「暂无待处理」，没有记录显示「未记录」。
4. 点击「生成报告文件」，生成当时的 JSON 报告和 CSV 条目明细。离开后从同批报告页的「历史报告」找回，已有文件不会随着当前数据变化重算。

## 数字怎样理解

- 一个报告对应一个现有导入批次。预检可导入数量不冒充已经入库；PDF 文字提取的输入单位是页，保留条目的单位是条。
- 两人独立提交表示当前轮次确有两名不同校对者提交，校对完成表示流程状态，不代表来源正确或已经被接收。
- 来源判断按历史提交字段及其最新保存判断统计，页面说明它不是最终条目正确率。判断覆盖不代替随机抽检。
- 相关编选记录展示保存时的完整范围；跨批或项目级数量不分摊成本批的采用数量。
- 交付包版本、正文数量和回执按实际记录展示。下载不自动变成接收成功。
- 完成时间、等待起点或正式抽样方法没有记录时保持未知，不用更新时刻推算。

## 实现边界

沿用项目管理权限、已有业务记录、串行作业队列和受保护的成果下载。新增 `batch_report_exports` 保存报告作业与附件索引。JSON 和 CSV 来自同一生成时点，历史文件保持不变；不修改既有 Review Bundle 或交付包协议。

本 PR 交付软件功能及合成材料上的操作演示。专业人员的来源判断、授权真实资料、实际接收及用户试用仍由对应人员执行。跨项目统一待办、编选例外和回执处置的集中工作台仍是原方案待完成部分。
