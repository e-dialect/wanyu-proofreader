# 万语校坊拼音转换：PR #306 系列简化修订

> 日期：2026-10-07
> 状态：根据本次访谈修订，替代此前讨论稿。
> 范围：当前莆仙方言既有方案的转换，先处理资料记录的本调。

## 1. 本次确定的方案

转换分成两条对应关系：

- **声母、韵母：来源拼写 → 来源 IPA → 目标拼写。** IPA 不同但资料明确给出对应的，可登记一条对应规则后自动转换。
- **声调：来源调号或调值 → 调类 → 目标调号。** 同属阴平的不同调值可以自动转换，不要求调值相等。

零声母统一使用字符串 `∅`。音段 IPA 和调值继续用字符串，保留现有 `notation`、`category`、`value`、`mark` 等字段即可。本轮不需要增加 `kind: zero`、调值整数数组、`realizations` 或独立的 `pivot_profile` 系统。

## 2. 零声母与喉塞音

`∅` 是本项目表示零声母的约定符号，不是一个实际发音。目标拼音不写声母时，`notation` 仍为空字符串；用于机器匹配的中间值则写 `∅`，避免把零声母与缺失资料混淆。

PR #306 的零声母条目可直接改成：

```json
{
  "notation": "",
  "ipa": "∅",
  "example": "乌 ou1 云 ong2",
  "note": "来源将本项归为零声母，IPA 栏原文为「ʔ/不标」；本项目按声母类别统一记作 ∅，实际出现的喉塞音保留在说明中。"
}
```

这是一处有说明的归一化，不再声称机器字段逐字照抄来源。来源页面及原文仍可通过现有出处和备注核对，不必另建一套原文数据结构。

区分以下情况即可：

| 情况 | 处理 |
| --- | --- |
| 来源方案明确归为零声母，可能读出 `ʔ` | 中间声母记 `∅`，发音说明放备注 |
| 来源明确把 `ʔ` 作为独立声母区分 | 保留 `ʔ`，按该方案对应规则处理 |
| 韵尾为 `ʔ`，如 `aʔ` | 保留在韵母中，不因零声母归一化而删除 |
| 韵尾为 `p/t/k` | 保留各自 IPA；有明确对应规则才转换到其他韵尾 |

IPA 的 `ʔ` 是喉塞音，`h` 是声门擦音，`p/t/k` 是其他发音部位的塞音。拼音字母另有方案自己的约定：当前目标方案声母 `h` 对应 IPA `h`，而 `ah` 的韵尾字母 `h` 对应 IPA `ʔ`。程序按声母、韵母分别查表，不做全局字符替换。

## 3. 声调按调类转换

当前目标方案有七个调类，对照如下。来源方案的数字编号必须按自己的说明解释，不能默认所有资料的 `1` 都表示阴平。

| 目标调号 | 调类 | 目标资料的调值 |
| --- | --- | --- |
| 1 | 阴平 | 533 |
| 2 | 阳平 | 13 |
| 3 | 上声 | 453 |
| 4 | 阴去 | 42 |
| 5 | 阳去 | 11 |
| 6 | 阴入 | 21 |
| 7 | 阳入 | 4 |

现有目标声调条目无需改成复杂结构：

```json
{
  "notation": "1",
  "category": "阴平",
  "value": "533",
  "mark": "gī",
  "example": "枝 gi1"
}
```

关键改动在转换规则：**`category` 是声调对应的共同键，`value` 是该来源或目标方案记录的调值。** 来源名称不同但说明明确等价的调类，可以在来源映射中统一命名。

以访谈中的调值举例，若各自资料都明确归为阴平：

| 来源记录 | 来源规则解释 | 目标输出 |
| --- | --- | --- |
| 来源 A 的 `533` | 阴平 | 调号 `1` |
| 来源 B 的 `544` | 阴平 | 调号 `1` |
| 来源 C 的 `33` | 阴平 | 调号 `1` |

这些是转换示意，具体来源与对应由真实方案说明填写。实现只需维护小表：`来源方案/口音 + 来源调号或调值 → 调类`，再查目标方案的 `调类 → 调号`。同一调类允许多个来源调值映入，不需要把各来源的所有调值都塞进目标的 `Tone.Value`。

输出的是目标拼音，原始拼音和 IPA 继续保存。调值不同但调类明确对应时可以自动输出；这不表示两个口音的实际音高完全相同。

若同一来源中的一个调值对应多个调类，可利用资料明确记载的韵尾或词项规则区分；仍无法唯一判断时，进入现有歧义复核。轻声、连读变调、代词特殊读法按具体材料登记特例，不为了填满七类而强行归类。

## 4. 三项工作的最小修改

### PR #306：目标方案清单

1. 将零声母的机器字段从 `ʔ/不标` 改为 `∅`，原文留在备注，并同步修改文件顶部的“逐字照抄”说明。
2. 保留 `Option.IPA` 和 `Tone.Value` 的字符串形状，保留现有七个声调条目。
3. `Pronunciations()` 只返回声母、韵母的 IPA；声调对应从 `Tones` 中读取 `Category` 与 `Notation`，不再将 `Tone.Value` 混入统一的 IPA 匹配表。
4. 保留 notation 唯一校验；允许资料中确有的“同 IPA、不同 notation”进入清单，由转换时返回候选，避免加载器拒绝真实方案。调值也无需唯一。
5. 继续保留出处、口音、例字和 NFC 处理；补充零声母及同音多候选的对应验证。

### #189：转换内核与来源规则

1. 逐本填写来源的声韵母 IPA 对照，以及调号/调值到调类的对应。
2. 声韵母按 IPA 或已登记的明确对应规则匹配；声调按调类匹配目标调号。
3. 来源写作零声母时统一到 `∅`。来源写作 `ʔ` 时，先按该来源的定义判断是否属于零声母，不做全局 `ʔ → ∅`。
4. 沿用现有状态：规则唯一确定输出则为 `EXACT`，多个候选为 `AMBIGUOUS`，没有对应为 `UNSUPPORTED`，人工结论沿用 `REVIEWED`。这里的 `EXACT` 表示规则给出唯一结果，不要求源、目标调值相同。

本轮不计算通用连读变调，也不自动寻找“最接近”的 IPA。必要的 schema 兼容调整随实际接入一起做，无需先建设通用框架。

### #289：批处理与复核

沿用现有运行面，消费 #189 的结果、候选和规则版本。能确定的转换自动通过，剩余项进入现有复核流程。

## 5. 验收看这五件事

- 目标零声母的机器值为 `∅`，输出拼音仍不添加声母字符。
- 已登记为阴平的不同来源调值都输出目标调号 `1`，不会仅因调值不同而报不支持。
- 韵母中的 `ʔ` 被保留，独立声母 `ʔ` 也不会被无条件删除。
- 声韵母 IPA 不同且没有明确对应时，不自动选取近似音。
- 同一输入产生多个合法目标时保留候选，不静默取第一项。
