# 界面契约

本文件记录已经落在 `frontend/src` 的行为。源码指针使用文件路径与选择器/导出名，避免格式化后行号漂移；本轮尚未完成的真人、原生设备及读屏验收见 `docs/evidence/workbench-experience-20261107/human-acceptance.md`。

## 基调与令牌

产品名为「万语校坊」。纸色底、墨色字、朱砂点缀来自 `style.css` 的 `:root`：`--paper`、`--ink`、`--accent`。颜色、圆角、层级、字体栈只在令牌定义处写字面值，调用点使用变量，不重新定义一套配色。

`--space-1` 至 `--space-6`、`--text-xs` 至 `--text-2xl`、`--radius-*`、`--z-*`、`--badge-*` 与状态色也定义在同一 `:root`。新组件使用这些刻度；常规界面15px、次级文字13.5px、辅助标注12px，校对输入18px。`--control-height` / `--control-height-sm` / `--control-height-touch` 分别为40/34/44px，手机主要触控目标至少44px。

字体约定：

- `--font-rare` 同时包含 `Fangji Phonetic` 与 `Fangji Rare Han`，不能遗漏任一家族。
- 普通界面与常规页标题使用 `--font-ui`，系统无衬线字体优先；音标字体不能放在 UI 字体栈首位，以免普通英文和数字混入记音字体。品牌和少量编辑性标题使用 `--font-display`，码位说明使用 `--font-mono`。
- 字段值、`.proofread-textarea.form-control`、`.final-value textarea`、`.ipa-key` 优先使用 `var(--font-rare), var(--font-ui)`；记音与缺字先由随附字体呈现，普通字符仍有系统回退。
- `AppFieldValue` 统一承载 `white-space: pre-wrap` 与 `overflow-wrap: anywhere`。调用方只负责间距、字号和布局，不再自行复制文本保真规则。
- 已明确的 IPA 字段使用 `lang="und-fonipa"`。未知方言转写不猜成英语或其他语言；来源明确时可显式传入语言。

字体覆盖集合由 `lib/fontCoverage.json` 给出，测试与原始字体 manifest/Unicode 范围精确比较。`useFontAvailability` 区分加载、失败与重试，并丢弃旧请求。含受保护字符时，加载完成前必须有提示；失败时保留原字符串与码位提示，不能用形近字替换。多个字段可以共用 `RareCharacterNotice`，并关闭子项重复提示。

UI 债务的实际判定由 `scripts/check_ui_debt.py` 与 `scripts/ui_debt_baseline.json` 执行。所有类别都为 fail 棘轮：静态内联样式为0，保留8处运行时进度/尺寸绑定；原生表格只有 `AppDataTable` 内1处；颜色、圆角、层级、缺角色提示、自制模态框、未定义变量和字体栈字面值债务均为0。上限只能下降。

## 领域编排与大视图

`ProjectDetailView` 与 `ProofreadEditorView` 都小于300行，只负责获取、编排和布局，不新增全局业务 store。

项目空间由 `lib/projectWorkspace.js` 映射为概览、材料、校勘、交付、设置五区。条目默认打开；初次成功统计确认为空项目时转入材料，不把读取失败误认为零条。PDF/CSV/Review Bundle/OCR、台账、导出、机器检查、归一等模块按需分包，首访才挂载，已打开面板在同项目切分区时保留，避免丢失预检、上传和未保存内容。跨模块刷新仍使用明确回调与事件，不新增全局业务 store。

设置按基本资料、校勘规则、成员与账号、输入工具、所有权分区读取和保存；无关资源失败不阻断基本资料。来源核验默认进入问题队列，核验约定可在设置中维护。问题列表与单事项详情分开，批量合并/拆分仍保留明确依据。编选和交付分别为列表、创建/准备、单批/单包详情，归一把转换作业与单条人工复核分开。

作业页使用 `DocumentReviewWorkspace.experience-workspace`。桌面默认45/55双栏，分隔条支持指针和方向键调整（30–65%）；来源页码、缩放、旋转与全屏合为一条工具栏。来源/约定默认摘要，阻塞、未完成或依据失配时自动展开。校对字段的编辑值与导入文本分别呈现，修改后才出现恢复操作。仲裁默认差异字段，来源复核和无差异情况展示全部字段，采用值不自动改变来源正误。

字符托盘默认关闭，开合与分栏按用户/项目存本机偏好；最近字符按精确值保留，搜索支持字符、提示和码位。不因搜索、缩放、托盘切换改变原字符串或光标选区。校对、租约、草稿、提交、退回及本人只读回看继续由原有 composables 和服务端裁决。

## Reka UI 精修样板

依赖锁定 Reka UI 2.11.0，公共外观集中在 `styles/ui-components.css`，不在业务页面直接散布组件库样式补丁。首批仅精修工作台、项目条目列表与桌面/手机校对，公共字体和控件令牌作为共享基础。其他旅程继续按此规范逐步迁移，不把首批验收等同全站验收。

工作台只有一个当前工作主入口，优先恢复仍可访问的工作；无当前工作时提升待仲裁或可领取工作。项目进展收为去重列表，读取失败仍显示错误与重试。项目条目默认关闭批量选择与高级筛选，URL已有筛选时展开对应筛选；普通待校对与质量待定分别以中性文字呈现，仲裁/异常继续突出。手机列表在同一表格内容列呈现进度与质量摘要，避免重复交互与整页横向滚动。

校对结果位于字段主体，导入文本作为紧凑对照；短字段可双列，多行字段自然跨列。textarea 按内容增高但保留可滚动上限，换行、空白、组合字符与选区不得被修整。手机原文入口在任务头，默认专注当前字段，字符搜索与分类压为一行。健康来源摘要紧凑呈现，失配/阻塞仍自动展开。

快捷键提示只呈现当前可用操作：单条进行中任务不提示方向切换，本人只读回看不提示保存或提交，回看邻居只展示实际可用的方向。方向键不创建第二个活跃任务，提交仍先打开核对确认。

动效统一使用 `--motion-fast` 120ms、`--motion-normal` 180ms、`--motion-slow` 220ms 与 `--ease-out`。按钮仅过渡颜色/边框，菜单淡入并小幅移动，字符托盘只在展开时入场；保存反馈按真实结果即时更新。减少动态效果设置关闭位移/入场动画。不得给 RouterView、任务/账号更换或权限失效添加延迟卸载，不得让动画改变光标、草稿落盘或服务端判断。

Reka 提供的运行时定位变量在 UI 债务检查中逐个登记；近似拼写仍报错。回归入口 `run_frontend_quality_browser.py --only components` 验证空值/数值选择、禁用/忙碌、键盘菜单、菜单到模态的焦点交接、窄屏弹层及减少动态效果；`workbench` 组包含真实临时后端的条目样板检查。

新手提示为三个可跳过、可重放的非模态小贴士，入口放在应用页眉，不占字段与底部导航区域，也不阻断编辑器快捷键。研究用途告知和提交前明确选择保持独立，不将查看/跳过提示当作同意。

纯拆分阶段的项目详情正常/空与禁用/错误三种状态，与原版整页 PNG 字节及管理请求顺序完全相同，见 `docs/evidence/backlog-20261106/`。最终界面另含本轮共享组件、字体、移动端和 OCR 的明确行为改动，不把阶段对照冒充最终界面零差异。

## 四态与读取生命周期

| 状态 | 语义 | 必须保留 |
| --- | --- | --- |
| pending | 请求未完成；骨架装饰节点 aria-hidden | 明确加载提示；已有成功结果可继续查看 |
| empty / none | 成功返回但没有记录或匹配 | 当前条件与清除/恢复入口 |
| empty / not_computed | 尚未运行计算 | 不能说成没有问题 |
| empty / not_authorized | 当前无查看权限 | 不能说成没有记录 |
| error | 本次读取失败 | role=alert、重试、已有成功值和用户输入 |
| danger | 不可逆或需认真确认的操作 | 明确文字、可见焦点、确认入口 |

成功/进行中的动态反馈使用 role=status；错误使用 role=alert；静态说明使用 role=note。状态不得只靠颜色表达。加载错误与操作错误分开：保存/校验失败显示在原编辑区，不得把输入和按钮一起隐藏。统计没取到时显示未知，不伪装成零。

读取资源的取消和代际保护由公共 helper 实现。查询切换、项目切换、卸载与迟到响应均不得复写当前数据。分页失败保留最后成功页与详情，重试针对原失败目标；成员候选游标同时绑定项目、操作者与查找词。

## OCR 界面边界

正式链只接收不含图像且可映射的单栏纯文字层页面。扫描引擎的离线实测发现难字静默替换，默认拒绝扫描，backend也独立拒绝实验worker的扫描输出发布。失败保留原 PDF，提示改用人工转录或CSV，不把错误猜测变成正式条目。

当前单栏输出不推断领域分列。原字符串、空格、坐标与识别时「确定/待确认/弃权」分别保留；确定不表示来源核验正确。管理修正不改原始识别记录。单作业最多200个物理页，超出明确要求分段。原始JSON通过管理权限接口下载，认证token不写入链接。

## 身份与离开页面的状态隔离

`App` 按当前账号重建受保护页面；退出和强制改密状态变化会重新执行既有路由门禁。公开登录页保留自己的原目标跳转，不因身份发布而提前销毁登录表单。项目管理子视图通过 `lib/adminRouteKey.js` 按路由名、项目和仲裁条目重建，查询条件变化仍保留当前工作区。

异步登录、外部绑定、身份刷新与资料保存只可向发出请求时的当前会话发布凭据；会话期间被退出或替换时，迟到结果不能恢复旧账号。账号变更也会清空权限上下文与共享请求，权限入口仍由既有服务端裁决。

同组件切换校对条目时，在清除保存计时器、替换页面引用之前立即落盘最后输入。来源或约定失配的本机旧草稿先归档再清除当前键；重读上下文不再次重置已经开始的新输入。核验面板的读取、排队草稿和问题提交均绑定任务代际，卸载使旧代际失效。归一复核只接受最后一次查询响应，刷新同条目保留人工填写，PDF 回退预览也按授权到期时间重新读取描述信息。

问题处理表单按事项保留已读取的基线。重新读取时，未修改表单同步最新记录；未保存草稿只在服务器版本不变时继续编辑。服务器版本变化时保留草稿并明确提示冲突，阻止保存，须先自行保留需要的文字、采用最新记录后重新编辑。保存成功按返回记录更新基线，保存期间追加的输入继续保留为未保存草稿。问题与来源复核的空列表均使用 `reason=none`，筛选为空时仍可切换范围。

### 归一草稿的依据变化

归一复核草稿按条目和完整复核依据共同绑定，同依据才保留可编辑内容。依据变化时只读归档旧写法/旧依据，当前表单清空并锁定；明确开始重新填写后才允许输入新结论。409后若新队列未成功加载，不能把旧来源重新标为当前依据。离页、筛选或已移出队列的工作区草稿有只读查看入口；关闭工作区前需自行保留，不冒充服务端已保存。API兼容与事务约束见 `docs/scheme-normalization-review.md`。
