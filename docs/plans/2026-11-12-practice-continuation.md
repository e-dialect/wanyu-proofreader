# 练习与正式工作的衔接

本轮承接《万语校坊专业团队版：21 天成熟度优化方案》中的角色清单、继续任务与提交后回看。重点是让人能找到正确项目、从当前步骤继续，并清楚区分练习记录与正式工作。

## 使用过程中发现的问题

- 正式项目打开材料指南后，旧练习区直接沿用其项目 ID，虚构资料导入入口可能指向正式项目。
- 从练习创建项目后直接进入材料页，原角色与步骤丢失；进入编选等独立页面也缺少返回练习的路径。
- 浏览器自记勾选容易被误看成工作完成，不能反映成员是否真正领取或提交。
- 最后一条提交成功后，结果藏在折叠说明里；领取失败、退回和释放会跳回未筛选任务大厅。原文还会错误显示租约失效。

## 本轮行为

创建时明确区分正式项目与练习项目，旧项目按正式用途读取，不凭名字推断；过去名称含“练习”的旧项目也不会自动改写用途，需创建明确标记的练习项目，原记录保留。练习只绑定服务端确认且当前角色有权使用的项目。原材料项目用于返回材料，与练习项目分别保留；创建后恢复练习步骤，业务页面可返回该步骤。项目列表与工作区标注练习用途。仓库自带完整虚构练习包不能导入正式项目，文件改名不改变判断；普通 CSV 不按文件名推测用途。

步骤以业务名称展示，当前查看位置保存在路由中，不再提供手工勾选完成。页面显示已入册条目、可用原文、成员、本人有效领取和当前轮真实提交等事实；管理员还能看到达到独立提交人数要求的条目数。读取不到保持未知，数量不代表学习合格、语言正确或接收方验收。来源标识放在可展开的核对详情中。

管理员可复制限定练习项目的校对者链接，校对者在该项目领取、提交、回看，并返回练习步骤。练习页提供返回任务或项目列表的入口，选择正式项目后继续工作；不移动练习数据，不自动授予资格。

提交成功但暂无下一条时明确呈现结果、项目内本人提交与可领取入口，焦点移到结果。成功提交后继续按既有本人提交权限查看原文，正常结束领取不显示为失败。领取失败、退回与释放保留原任务列表上下文。

## 实现和交付边界

本 PR 基于 #432，复用其角色指南和项目工作区；与 #435 的材料流程、#437 的项目概览分别评审。

新增 `projects.purpose` 可选字段和只读练习事实接口。用途由创建入口设置且项目设置不允许改写；旧空值按正式用途读取。已有练习项目时迁移回退拒绝删除用途字段。发布需保持前后端和迁移匹配；不要通过删除练习标识来回退，旧版界面不能提供本版的用途区分。无新环境变量，不自动创建账号、不绕过项目创建额度或业务权限。

本轮实际操作使用隔离服务、仓库虚构练习材料和演示账号。仍需原方案中的真人、语言专家及接收方参与；开发演练不能代替这些证据。平台继续围绕有出处、能复核、能协作的材料整理，长期的多模态在地文化知识生成不作为本轮能力承诺。
